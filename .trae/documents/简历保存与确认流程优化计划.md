# 简历保存与确认流程优化计划

## 问题分析

### 问题1：确认保存不生效，延迟保存
**现象**：
- 点击确认按钮后没有保存
- 之后修改名字再点击确认时，却把之前没有保存的简历信息也一起保存了

**根本原因**：
- `pending_confirmation` 状态保存在数据库中，但可能在某些情况下没有正确传递到 `tool_node`
- 或者确认回复处理时，`state.pending_confirmation` 为 None

**解决方案**：
1. 确保 `pending_confirmation` 正确从数据库加载到 state
2. 确保确认回复处理时能正确匹配 confirm_id
3. 添加调试日志追踪问题

---

### 问题2：CONFIRM_MARKER 直接输出到界面（偶发）

**用户观察**：
- 截图1：直接输出 `[CONFIRM_MARKER:{...}]` - 没有正常回复
- 截图2：正常输出"没问题，黄伟濠！..." - 有正常回复

**为什么偶发？根本原因已查明**：

当 LLM 决定调用工具（save_resume_tool）时，它会生成一个 `AIMessage`，但这个消息可能有两种情况：

**情况A（截图1的问题）**：
- `AIMessage` 只有 `tool_calls`，没有 `content`（文本内容为空）
- 这是 OpenAI 函数调用的正常行为
- 然后 `tool_node` 生成 `ToolMessage`，内容是 `[CONFIRM_MARKER:...]`
- 在 `mcp_service_simple.py` 第 1075-1083 行查找回复时：
  - 找到 `AIMessage`，但 `content` 为空，跳过
  - 找到 `ToolMessage`，使用其内容 `[CONFIRM_MARKER:...]`
- 结果：用户看到 CONFIRM_MARKER

**情况B（截图2的正常情况）**：
- `AIMessage` 既有 `tool_calls`，又有 `content`（文本内容不为空）
- 在 `mcp_service_simple.py` 第 1075-1083 行查找回复时：
  - 找到 `AIMessage`，`content` 不为空，使用它
- 结果：用户看到正常回复

**为什么 LLM 有时候输出 content，有时候不输出？**
- 这是 LLM 的不确定性行为
- 有时候 LLM 只输出工具调用，不输出解释文本
- 有时候 LLM 会同时输出工具调用和解释文本

---

## 解决方案

### 方案1：修改 tool_node，添加默认回复（推荐）

在 `tool_node` 中，当生成 `pending_confirmation` 时，同时生成一个友好的 `AIMessage` 作为回复：

**文件**：`resume_agent.py`

**修改位置**：`tool_node` 函数（第 882-914 行）

**修改内容**：
```python
# 修改前
if tool_name == 'save_resume_tool':
    content = tool_args.get('content', '')
    try:
        updated_resume_data = json.loads(content)
    except json.JSONDecodeError:
        updated_resume_data = None
    
    # 传递 user_id
    tool_args['user_id'] = state.user_id
    
    # 生成确认标记，返回给前端
    confirm_id = str(uuid.uuid4())[:8]
    pending_confirmation = {...}
    
    # 返回确认标记
    marker = {...}
    result = f"[CONFIRM_MARKER:{json.dumps(marker)}]"

# 修改后
if tool_name == 'save_resume_tool':
    content = tool_args.get('content', '')
    try:
        updated_resume_data = json.loads(content)
    except json.JSONDecodeError:
        updated_resume_data = None
    
    # 传递 user_id
    tool_args['user_id'] = state.user_id
    
    # 生成确认标记，返回给前端
    confirm_id = str(uuid.uuid4())[:8]
    pending_confirmation = {...}
    
    # 生成友好的确认提示（作为 ToolMessage 的内容）
    result = "我已为您准备好简历修改方案，请确认是否应用这些更改？"
    
    # 同时生成一个 AIMessage 添加到消息列表
    confirm_ai_message = AIMessage(content="我已为您准备好简历修改方案，请确认是否应用这些更改？")
    new_messages.append(confirm_ai_message)
```

### 方案2：修改 mcp_service_simple.py，过滤 CONFIRM_MARKER

在 `mcp_service_simple.py` 第 1075-1083 行，不返回 `ToolMessage` 的内容，而是返回默认提示：

```python
# 修改前
if not accumulated_content:
    for msg in reversed(messages_list):
        if isinstance(msg, AIMessage) and msg.content:
            final_content = str(msg.content)
            break
        # 也检查 ToolMessage
        if isinstance(msg, ToolMessage) and msg.content:
            final_content = str(msg.content)
            break

# 修改后
if not accumulated_content:
    for msg in reversed(messages_list):
        if isinstance(msg, AIMessage) and msg.content:
            final_content = str(msg.content)
            break
    # 如果没有找到 AIMessage，使用默认提示（不返回 ToolMessage 内容）
    if not final_content:
        final_content = "请确认是否保存修改？"
```

---

## 推荐方案

**推荐方案1**，因为：
1. 更灵活，可以在 tool_node 中自定义确认提示文案
2. 符合 LangGraph 的设计理念（节点负责生成消息）
3. 不依赖后端的 fallback 逻辑

## 优化计划

### 阶段1：修复 CONFIRM_MARKER 显示问题

**文件**：`resume_agent.py`

**修改**：`tool_node` 函数，当调用 `save_resume_tool` 时，生成友好的确认提示而不是 CONFIRM_MARKER

### 阶段2：排查确认保存不生效问题

**排查步骤**：
1. 在 `tool_node` 中添加日志，打印 `state.pending_confirmation`
2. 检查确认回复处理时是否能找到对应的待确认数据
3. 检查 confirm_id 是否匹配

### 阶段3：验证修复

**测试场景**：
1. 发送简历图片 → AI 识别 → 检查是否显示正常回复（不是 CONFIRM_MARKER）
2. 多次测试，确保不再偶发显示 CONFIRM_MARKER
3. 点击确认 → 验证是否保存成功
