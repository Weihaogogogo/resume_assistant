# 上下文摘要功能优化方案

## 一、问题概述

### 1.1 当前实现

* **触发条件**：当人类消息超过 20 条时触发压缩

* **保留策略**：保留最近 5 条消息不压缩

* **输入处理**：每条消息取前 300 字符

* **摘要要求**：不超过 1000 字

* **实际效果**：仅能压缩到 300 多字

### 1.2 问题表现

* 设置了 1000 字限制，但实际只能压缩到 300 多字

* 信息密度未达预期

* 关键信息可能在截取过程中丢失

***

## 二、核心问题分析

### 2.1 当前 Prompt 的问题

**当前 Prompt 关注点错误**：

```
2. 保留关键信息：用户基本信息、工作经历、教育背景、已完成的修改、当前上下文
```

**问题**：这些信息已经在 `resume_data` 中存在，重复保存在摘要中没有意义。

### 2.2 正确的方向

**应该关注的是用户在对话中提到的个性化信息**：

* 用户提及的个人经历、故事、背景

* 用户的具体要求、偏好、期望

* 用户的性格特点、沟通风格

* 用户对简历修改的具体意见

* 用户明确表达过的偏好和禁忌

* 重要的上下文（如用户的职业规划、特殊需求等）

***

## 三、优化方案

### 3.1 重新设计的 Prompt

```
你是高效的对话压缩专家。你的任务是将对话压缩到指定长度，保留最有价值的个性化信息。

## 重要原则
- 用户的姓名、目标岗位、技能、工作经历、教育背景等结构化信息已在简历数据中保存，**无需在摘要中重复**
- 摘要只需记录用户在**对话中提及的个性化信息**

## 压缩目标
- 输出长度：800-1000 字
- 每个字都要有价值

## 必须保留的信息（按优先级）

1. **讨论过的话题**
   - 用户和 AI 讨论过哪些主题/话题
   - 每个话题的关键结论或进展
   - 哪些话题已结束、哪些还在进行中

2. **用户明确表达的要求和偏好**
   - 用户对简历的具体修改要求
   - 用户提到的工作偏好、城市偏好、薪资期望等
   - 用户明确拒绝或喜欢的风格

3. **用户提及的个人背景**
   - 用户在对话中提到的额外经历、故事
   - 用户口头补充的信息（不在简历中的）
   - 用户的职业规划、转型原因等

4. **用户的性格特点**
   - 用户的沟通风格（简洁话唠严肃幽默等）
   - 用户做决策的方式（犹豫果断犹豫等）
   - 用户的特殊习惯或偏好

5. **修改历史和决策**
   - 用户确认过的修改点
   - 用户拒绝过的建议
   - 用户特别满意的修改

6. **当前上下文**
   - 用户当前最关心的问题
   - 当前对话的主题

## 可以丢弃的信息
- 简历中已有的结构化信息（姓名、岗位、技能等）
- 客套话、寒暄
- LLM 的解释性内容
- 重复的表达

## 输出格式
【讨论话题】列出所有讨论过的话题及关键结论
【用户个性化信息】用户提及的个人要求、偏好、背景等
【修改决策】确认的修改点、拒绝的建议
【当前状态】用户当前的需求和关注点
【重要备注】其他需要记住的个性化信息
```

### 3.2 优化输入处理

**改进点**：

1. 增加截取长度到 500 字符（原来 300 太少）
2. 对工具调用结果进行特殊处理，提取修改点
3. 识别并标记用户的重要表述

```python
# 改进输入处理逻辑
for msg in early_messages:
    role = getattr(msg, 'role', 'unknown')
    content = getattr(msg, 'content', str(msg))
    
    # 如果是工具调用（save_resume_tool），提取修改内容
    if "save_resume_tool" in str(content):
        content = extract_tool_result_summary(content)
    else:
        content = str(content)[:500]  # 增加到 500
    
    conversation_text += f"【{role}】{content}\n"
```

### 3.3 参数调整

```python
# 当前
MAX_HUMAN_MESSAGES = 20

# 建议
MAX_HUMAN_MESSAGES = 15  # 更早触发压缩
```
